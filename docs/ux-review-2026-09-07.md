# Rehearse experience review — 2026-09-07

## Assessment and review scope

The product has a coherent topic → sources → quiz → repair → recall loop, a distinctive leaf-map direction, and useful evidence rules. The largest UX gaps are continuity, orientation, and trust in progress. Keep the soft green/white identity and restrained screens; add the information necessary to answer: What should I do now? Is my work saved? What have I learned? What remains?

The original audit below records the pre-fix experience. The implementation follow-up at the end distinguishes shipped fixes from remaining work; original observations are retained as reproduction evidence.

- **Browser-observed:** local landing and login pages; public `/demo` recall, answer reveal, self-rating, result explanation, and compact Tree; desktop 1280×720 and mobile 390×844 screenshots. No errors or warnings were captured in the inspected tab.
- **Code-inspected:** authenticated Today/Progress, source setup, initial quiz, recall, remediation, canvas, connection management, authentication recovery, and the local generator.
- **Verification:** four existing unit suites passed, 21 tests total: Today selection, initial quiz, tree rendering, and password recovery.
- **Authenticated follow-up:** After the user explicitly authorized login, reviewed `demo@rehearse.local` through topic creation, pasted-source import, local quiz generation, mixed quiz completion, cited repair, Today, Progress, and recall draft recovery. Inspected the interactive constellation on desktop and at 390×844; tested zoom/reset and arrow-key selection. No errors or warnings were returned by the inspected tab's captured logs.
- **Remaining limits:** This is not a complete accessibility or production reliability certification. Real-device touch/pinch, screen readers, expired-session recovery, offline/server-failure injection, PDF/URL import, a one-node fixture, and 50-node performance remain unverified live. The public demo uses the compact tree, not the interactive constellation.

## Must fix before a public account-based release

### 1. Preserve the initial quiz across interruptions

**Code finding:** `src/components/learning/initial-quiz.tsx:214` stores answers, phase, and position in component state. Its request at line 276 saves only the completed attempt. Scheduled recall already has server checkpoints, but the initial quiz does not. A refresh or route exit loses an unfinished initial attempt. Source and quiz routes also redirect unauthenticated visitors to login without their destination.

**Reproduced live:** Answered question 1, advanced to question 2, typed a short response, then refreshed. The quiz returned to unanswered question 1; both position and draft were lost. In contrast, a scheduled recall displayed Saved and restored its exact answer after refresh.

**Required experience:** Save and resume initial quizzes, show a discreet save indicator, and preserve the exact destination through reauthentication. Provide a bounded failure state and retry when saving stalls. Extend draft protection to authored sources and repair answers where appropriate.

**Acceptance:** Refresh during question 3, feedback, and final submission; restore the same attempt and stage. Expired authentication returns to that attempt after sign-in. Retry cannot create duplicate evidence. Users can distinguish saved, saving, and unsaved work.

### 2. Make Progress independent of Today

**Code finding:** `src/app/progress/page.tsx:20` uses `getTodayData`, which returns one recommended action. When that action is Strengthen or setup, Progress displays “Your learning evidence will appear here,” even if other skills already have evidence. Otherwise it reports one skill rather than the user's overall progress.

**Reproduced live:** The seeded Idempotent operations leaf was Well learned. After the audit quiz saved with one missed answer, Progress showed the empty-state message instead of existing evidence.

**Required experience:** Query progress separately. Show all assessed skills, recent changes, and each skill's evidence history. Keep the default compact, with drill-down for detail.

**Acceptance:** With several learned skills and one open repair task, all prior evidence remains visible. Changing today's recommendation does not change or erase the progress summary. Empty state appears only when there is actually no evidence.

### 3. Respect the skill the user chose

**Code finding:** `src/lib/learning/today-query.ts:144` prioritizes any active session and then any repair before honoring `preferredGoalSkillId`. A Tree “Review now” link for Arrays can therefore present Hashmaps instead. The selector also returns a current scheduled skill before an incomplete setup, leaving unfinished work undiscoverable from Today.

**Reproduced live:** Clicked Review now on Idempotent operations. The URL retained `?skill=local-demo-goal-skill`, but Today displayed Core idea → Strengthen for UX audit — Hashmaps, with no explanation of the substitution.

**Required experience:** Separate an explicit skill action from a general recommendation. If another session prevents starting, explain it and offer a clear resume/switch decision. Keep incomplete setup reachable through a small secondary row.

**Acceptance:** Selecting Arrays opens Arrays or explicitly explains a conflict. Today shows one primary recommendation plus a due count and access to other due skills/drafts. A repair does not silently hide the rest of the workload.

### 4. Fix the clipped mobile map and canvas recovery

**Reproduced live — launch blocker:** At 390×844 with five skills, the mobile list is almost entirely clipped and Connect extends beyond the visible frame. DOM measurements show a 574.8px node list inside a 25.6px stage, inside a 96.6px frame with `overflow: clip`. The absolutely positioned `.constellation-viewport` (`src/app/globals.css:521`) remains out of normal flow when mobile CSS makes the stage height auto. The list therefore does not establish the parent height. The controls extend to roughly x=448 in a 390px viewport.

**Code finding:** `src/components/learning/skill-constellation.tsx:436` disables zoom/reset for fewer than two leaves, while pan and wheel handlers allow one leaf. Pan is unbounded, Reset returns to the origin rather than fitting content, and canvas height increases with node count. The stage keeps `touchAction: "none"` and transforms at line 490 even when mobile CSS presents it as a normal list. No two-pointer pinch handler is implemented.

**Required experience:** Restore normal-flow sizing for the mobile list, disable canvas transforms/gesture interception in list mode, and fit or wrap its toolbar. Enable recovery controls whenever the viewport changes, including with one node. Provide Fit all and reveal selected node; keep a bounded desktop viewport. Separate desktop canvas gestures from mobile list scrolling. Verify trackpad scroll versus zoom deliberately.

**Acceptance:** All skills and Connect are visible/reachable at 320px and 390px widths; the list establishes its container height. One leaf can always be recovered after pan/zoom. At 1, 10, and 50 leaves, Fit all exposes the map and keyboard selection keeps the selected node visible. The mobile list scrolls normally without being transformed accidentally. If mobile canvas mode is offered, pinch and pan work without blocking access to the rest of the page.

### 5. Complete account recovery and durable ownership

**Code finding:** Login exposes “Forgot password?” but `src/app/auth/reset-password/page.tsx` says recovery is unavailable, and its API returns 503. The account menu contains identity and sign-out only. The README identifies SQLite and filesystem uploads as local-only persistence.

**Required experience:** Before accepting real accounts, provide password recovery, account settings, reliable persistence across deployments, and a documented export/deletion path. Add timezone editing alongside any future reminder preferences.

**Acceptance:** A learner can recover access and see the same skills on another device. A deployment does not lose accounts or sources. An account cannot access another user's sources or evidence. Recovery and expiry have understandable, actionable states.

## Essential additions for a high-quality MVP

### 6. Give each skill a real home

**Code finding:** In `SkillPrimaryAction` (`skill-constellation.tsx:127`), “Open skill” goes to Add sources. The source screen lists names/locators and offers generation, but no dedicated overview or source preview/edit/removal controls. A returning learner is sent back into setup instead of to their learning history.

**Reproduced live:** Open skill on HTTP caching displayed Step 2 of 3 → Add sources rather than a skill overview. The seeded demo's status and missing sources are synthetic fixture properties, not proof that a real learner's evidence disappeared.

**Add:** A compact skill overview with scope, source access, next recall, learning gaps, and evidence. Its main action should adapt to Draft, Quiz ready, Repair needed, Recall due, or Current. Put rename/archive and source management under a secondary menu.

**Acceptance:** From any leaf, a learner can inspect what it covers, open a cited source, resume the correct activity, and manage the skill. “Open skill” does not require redoing setup or generating another pack. Replacing a source explains what happens to existing questions and historical evidence.

### 7. Make “Well learned” the product's meaningful payoff

**Observed:** The public demo shows the milestone as a small badge above “Review saved”; an explanation is behind “Why this changed.” The state is visible, but the moment is easy to overlook.

**Add:** A restrained first-time milestone: “You've learned Accessible buttons well,” followed by the precise scope and maintenance date. Before the milestone, show a short, evidence-derived explanation of what remains (coverage, spaced recall, or new-angle checks). Let users open the full evidence history.

**Acceptance:** The milestone appears once per qualifying transition, respects reduced motion, and is announced accessibly. Every requirement shown comes from the actual policy. Wording distinguishes self-rated evidence from objective grading and never implies permanent mastery or mastery of an entire broad topic from a narrow source.

### 8. Make self-quizzing easier to understand

**Code/observed finding:** Initial quiz uses “Missed / Partial / Meets”; recall uses effort-based choices. Reference answers and source disclosures exist, but there is no learner-facing question-report/exclusion action in the reviewed quiz interfaces. The local generator deliberately uses generic competencies and predictable answer choices; it is a test fixture, not a learning-quality benchmark.

**Add now:** Consistent rating language; concrete short-answer criteria; “I don't know” that does not require typing a placeholder answer; a question count and approximate duration; a way to flag an ambiguous or incorrect item. Offer an optional cited “Review key ideas” step for someone learning a topic for the first time, without forcing it on someone ready to quiz.

**Acceptance:** A learner can distinguish correctness from effort and knows short answers are self-rated. A reported flawed question has a clear status and cannot quietly distort future mastery. Every miss has a specific cited repair and later unassisted retry.

**Later AI gate:** Evaluate representative packs for plausible distractors, named competencies, citation support, answer rubrics, and fair new-angle questions. Keep AI deferred as agreed; clearly label deterministic preview content until that work ships.

### 9. Complete direct map interaction and discovery

**Code finding:** Nodes have index-based positions. Connect scrolls to a separate form and does not initialize its From field from the selected node. Connections can be created or removed, but the current interface does not offer line drawing, node placement, connection editing, or undo. The CSS changes the map into a list on mobile, with no desktop list toggle/search/filter controls.

**Reproduced live:** Selected HTTP caching, clicked Connect, and the form's From remained Idempotent operations. Desktop Zoom in changed 100% to 118%, Reset restored 100%, and ArrowRight selected/focused the next leaf successfully.

**Add:** Saved node positions, source-node → target-node connection mode, keyboard/tap equivalents, editing and Undo. Add search, a small state filter, and explicit Map/List switching. Keep all new leaves independent and future automatic tree generation deferred.

**Acceptance:** Select Hashmaps, choose Connect, then Arrays; Hashmaps is preselected. The equivalent action works without dragging. Moving or connecting skills does not alter evidence. Positions survive reload, and an accidental connection removal can be undone. A learner can find one skill among 50 without scanning the whole map.

### 10. Make asynchronous work and failures legible

**Code finding:** Source/generation forms expose inline errors and pending labels, but no durable processing progress/resume UI. Connection removal catches failures and returns without a user-facing error (`src/app/actions/skill-relationships.ts`). No route-level `loading.tsx`, `error.tsx`, or custom `not-found.tsx` files were found under `src/app`.

**Add:** Clear source states (reading, ready, needs attention), actionable retry, route recovery, and explicit mutation success/failure. A successful import should offer a preview of the extracted content so the learner can verify the correct material was read.

**Acceptance:** Failed URL extraction offers a reason and paste-text fallback. Unreadable PDFs explain the limitation. Slow generation does not leave an indefinite unexplained button spinner; returning later restores job status. Failed connection removal retains the visible line and explains the failure.

## Visual refinements without adding clutter

- Keep white and light green surfaces, leaf geometry, and restrained typography. Use the strongest green for the next action and meaningful milestones.
- Add one line of context where it resolves uncertainty: “3 skills due · about 8 min,” “Saved,” or “One more spaced check needed.” Do not populate empty space with decorative dashboard statistics.
- Use “Skill Map” for the independent-node canvas and “tree” for a connected group, matching the accepted product model.
- Make secondary actions contextual to the selected skill; avoid making learners travel to an unrelated form beneath a long map.
- Update the local landing copy, which still says connected branches are next (`src/app/page.tsx:67`). The public demo should eventually demonstrate topic → source → mixed quiz → repair → recall → multiple leaves, rather than only a single synthetic recall and compact card.
- Explain the demo's preloaded evidence before a single answer produces Well learned; the current flow can otherwise suggest one quiz answer establishes mastery.

## Suggested delivery order and exit checks

1. **Continuity and correctness:** clipped mobile map/toolbar, initial-quiz resume, explicit-skill routing, independent Progress, one-node canvas recovery, mobile scroll behavior.
2. **Product completeness:** skill overview, source management, workload visibility, clear rating/milestone explanations, question reporting.
3. **Map polish:** saved placement, direct connections, undo, fit/search/filter, accessible list parity.
4. **Public release:** account recovery, managed persistence, meaningful loading/error recovery, production-quality learning content evaluation, representative public demo.

Keep the main plan as the architecture/specification reference; this review supplies a practical sequence of UX fixes rather than another broad rewrite.

Before calling the experience high quality, test a fresh learner and a returning learner with multiple skills through the full flow on desktop and mobile. Include keyboard-only operation, mid-quiz refresh, expired login, failed source import, failed save, one-node pan recovery, 50-node discovery, and a Well learned transition. Passing unit tests alone does not verify these experiences. Observe whether testers can identify their next action, saved state, and reason for their learning state without verbal coaching.

inside the map. The fixes expose selectable line targets with Disconnect, a
selected-skill connection list, mobile inline Disconnect, and a visible Undo
